# Show HN

## Verdict

**P1 — potentially high-quality technical discovery, highly unpredictable.**
The project qualifies only when HN readers can install and run it from the
public repository without a signup wall.

**Status:** blocked on the public repository and a successful clean remote
install. Nothing has been submitted.

## Current official submission path

Submit the original public repository to Hacker News with a title beginning
`Show HN:`. Every submission first appears on `shownew`; it reaches the Show
page after a small points threshold. Placement is never guaranteed.

Sources: [official Show HN rules](https://news.ycombinator.com/showhn.html) and
[HN guidelines](https://news.ycombinator.com/newsguidelines.html).

## Prerequisites

- Public GitHub repository.
- One-command install works for an unauthenticated reader.
- At least one concrete persona walkthrough is easy to inspect.
- The author is available to answer technical and skeptical questions.
- The author's HN use is not primarily promotional.
- No request for votes or comments anywhere.

## Listing title

> Show HN: MoneyPrinter.md – revenue skills that separate real cash from AI hype

## Short description

HN has no short-description field. The factual one-line summary for the owner's
own preparation is:

> Seven open-source Agent Skills route a short business interview to one bounded
> payable test while keeping cash separate from pipeline, estimates, and
> simulations.

Do not paste that line as an HN comment.

## Long description

HN has no long-description field. The first explanatory comment must be written
by the owner under the body rule below.

## Body rule

HN's current guidelines tell commenters not to post generated or AI-edited
text. The explanation beneath a Show HN is a comment, so this packet
deliberately does **not** provide paste-ready body prose. The owner should write
it personally.

## Human-authored body checklist

In the owner's own words, cover:

1. What personally bothered you about AI “money printer” repositories.
2. Why you chose plain `SKILL.md` files rather than an opaque application.
3. The seven economic evidence labels and why the distinction matters.
4. How the short interview routes the five included personas differently.
5. The exact one-line install and what a reader can try immediately.
6. What remains unproven: real customer outcomes and per-host activation.
7. The technical or product feedback you genuinely want.

Do not mention Ko-fi in the title or opening explanation.

## Tags

HN has no listing tags. The repository itself should use relevant GitHub topics.

## Links required

- Submit the public GitHub repository as the original source.
- Link the landing page only inside the repository or a later answer if useful.

## Assets required

None. HN rewards a runnable project and substantive discussion, not a launch
graphic.

## Expected discovery mechanism

- `shownew` for all Show HN submissions.
- Show page after a small points threshold.
- Possible front-page placement and technical discussion, with no guarantee.

## Review risks

- A text-only repository can be mistaken for “other reading material.” The
  working install and runnable workflow must be obvious.
- Generic marketing language, exaggerated claims, or donation emphasis will
  hurt credibility.
- Asking friends or followers to upvote/comment violates the rules.
- Copying an AI-written first comment would conflict with HN's current
  human-conversation rule.

## Final human action

Run the clean install, submit the public repo with the exact title, write the
first comment personally from the checklist, and stay available for candid
questions.
