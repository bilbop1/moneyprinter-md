# Funding and the voluntary 1% pledge

If MoneyPrinter produces attributable profit for you, consider voluntarily
returning 1% of that profit through Ko-fi. No tracking and no obligation. It
funds source review, compatibility checks, and new field-tested playbooks.

This is a social contract, not a license term, purchase requirement, success
fee, or earnings claim. The repository remains usable without payment. The
project does not ask users to disclose profit, revenue, customers, payment
records, or personal information in order to use the skills.

## Why there is no live funding file yet

The repository intentionally does **not** include `.github/FUNDING.yml` until
the owner supplies the exact Ko-fi username. A display name, email address,
website, or presumed handle is not enough. Using the wrong handle would route
donations incorrectly.

After the owner confirms the exact username, create the file with the value
verbatim under GitHub's `ko_fi` key:

```yaml
ko_fi: exact-confirmed-username
```

Replace `exact-confirmed-username` only with the owner's confirmed Ko-fi
username. Do not infer it from `bilbop.org`, a GitHub username, or a display
name. Then verify the funding link in GitHub's repository UI before announcing
it publicly. GitHub documents the supported funding-file format in
[Configuring funding for your repository](https://docs.github.com/en/sponsors/setting-up-github-sponsors-for-your-repository/configuring-funding-for-your-repository).

Until that confirmation exists, any donation language should link to this
explanation rather than a guessed payment destination.
